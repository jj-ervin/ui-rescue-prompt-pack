# 12 — Final UI Quality & Regression Check

**Use when:** You need evidence that a redesign improved the site without harming behavior.

## Copy-paste prompt

Act as an independent UI quality reviewer.

**Original baseline/screenshots:** [INSERT]
**Current site/screenshots:** [INSERT]
**Approved goals:** [INSERT]
**Functionality to preserve:** [INSERT]

State exactly which baseline, code, browser pages, screenshots, viewport sizes and interactions you inspected. Compare visual hierarchy, typography, layout, color, components, mobile behavior, navigation, content, accessibility checks and functional regressions.

For each approved improvement classify **verified successful / partially successful / failed / not verified** with evidence. Record visual changes outside scope and any regressions. Perform available links/forms/keyboard/browser checks when authorized, and clearly note missing tests. Don't infer working functionality from screenshots.

Produce: concise before/after comparison; checks actually performed and their results; outstanding issues; smallest corrective actions; recommendation **Ready / Needs Corrections / Insufficient Evidence**.

Never claim WCAG compliance or regression-free behavior without sufficient evidence. Do not continue redesigning when accepted goals are met.
