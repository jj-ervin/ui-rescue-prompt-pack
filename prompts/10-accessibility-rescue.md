# 10 — Accessibility Rescue

**Use when:** You want an evidence-based accessibility improvement plan.

## Copy-paste prompt

Act as an accessibility-focused UI reviewer familiar with **WCAG 2.2 Level AA**.

**Website or materials:** [INSERT]

Report what was actually reviewed (screenshots, DOM/source, browser, assistive tech, keyboard operation). Evaluate only assessable areas: contrast, text resizing/reflow, semantic heading structure, form labels/errors, keyboard access, visible focus, link purpose, touch targets, navigation, motion and text alternatives.

For each finding state the observed or suspected barrier, precise location, affected users, relevant WCAG success criterion if applicable, recommended fix and how to verify. Separate **confirmed**, **possible**, and **not tested**. Rank blockers affecting essential tasks highest.

Never claim completed conformance, legal compliance, or assistive-technology verification that did not happen. Don't remove content/functionality as a shortcut. Provide a remediation plan and **stop for approval.**

## Working rules
- Inspect actual available materials; distinguish proven issues from possible ones.
- Preserve functionality, brand, content meaning, framework, and working integrations absent explicit approval.
- Do not invent measurements, verification results, or conformance claims.
